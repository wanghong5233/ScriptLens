# ScriptLens 10 天交付计划

## 1. 交付目标

10 天后交付一个可体验、可部署、可评估、带加分项的剧本解析 Agent。

最终交付必须包含:

- 线上 Web demo。
- 可运行本地项目。
- 示例剧本。
- 结构化报告。
- 原文证据定位。
- 多轮追问。
- 多视角分析。
- 数据评分。
- 低分项改写。
- skill/反馈机制。
- 评估方法和评估报告。
- README 和展示材料。

## 2. 总体节奏

D1-D2 做清楚"为什么这样做"。

D3-D8 做出核心产品和加分项。

D9-D10 做部署、验收、修 bug 和展示材料。

原则:

- 每天结束必须有可验收产物。
- 不允许连续两天只有概念没有可运行东西。
- D6 前必须能看到前端报告页。
- D8 前必须跑通全部加分项雏形。
- D9 后只修 bug 和打磨,不引入新大功能。

## 3. D1:需求拆解 + 竞品调研

目标:

- 把任务文档拆成可验收需求。
- 明确这不是摘要项目。
- 形成垂直竞品参照。

产物:

- `docs/01-requirements.md`
- `docs/03-competitor-scan.md`

验收:

- 能逐条说明题目要求如何在产品中体现。
- 能说清楚 ScriptLens 和普通摘要器的差异。
- 能说清楚借鉴哪些垂直产品能力。

## 4. D2:方案调研 + 产品设计 + 架构 + 评估

目标:

- 定义技术路线。
- 定义 demo 体验。
- 定义模块边界。
- 定义评估方法。

产物:

- `docs/02-evaluation.md`
- `docs/04-solution-research.md`
- `docs/05-product-design.md`
- `docs/06-architecture.md`
- `docs/07-bonus-plan.md`
- `docs/08-delivery-plan.md`
- `docs/09-engineering-rules.md`

验收:

- 能从文档直接进入 build。
- 能画出用户流程和技术数据流。
- 能说明每个加分项如何被 demo 看到。

## 5. D3:仓库初始化 + 上传/解析/基础报告

目标:

- 建立可运行项目骨架。
- 跑通上传文本到基础报告的最短链路。

任务:

- 初始化 Python 后端和 Web 前端。
- 建立 `scripts/segments/reports` 数据模型。
- 实现上传或粘贴文本。
- 实现基础文本清洗和分段。
- 实现 LLM 生成基础 report。
- 加入示例剧本入口。

验收:

- 本地启动前后端。
- 上传 `samples/xiaoqie.txt`。
- 返回基础报告。
- 不要求证据联动完整,但字段结构稳定。

## 6. D4:证据定位 + 多轮问答

目标:

- 让报告结论可追溯。
- 让用户可以围绕剧本追问。

任务:

- 建立 `EvidenceRef`。
- 报告中的核心结论绑定证据。
- 前端点击证据跳转原文。
- 实现 `POST /chat`。
- 问答回答返回证据和置信度。

验收:

- 点击"关键反转"能跳原文。
- 追问"陆寻为什么赶走秀秀?"能基于证据回答。
- 无证据问题不强答。

## 7. D5:Scorecard + 数据分析 + Eval

目标:

- 完成加分项 #2 和 #3 的核心。

任务:

- 实现 scorecard schema。
- 生成维度评分、理由、证据。
- 前端展示评分图。
- 建立 `eval/fixtures` 和 `eval/golden`。
- 实现 `make eval`。
- 生成第一份 eval report。

验收:

- 报告显示评分。
- 每个评分有依据。
- eval 命令可运行。
- eval report 有失败样例和指标。

## 8. D6:前端报告页 + 真实展示体验

目标:

- 完成加分项 #6 的核心。
- 让 demo 第一眼成立。

任务:

- 完成左右布局。
- 完成决策卡片。
- 完成报告分层。
- 完成视角切换。
- 完成原文证据高亮。
- 完成追问入口。

验收:

- 评估方打开页面能直接理解产品。
- 30 秒内看到是否值得继续看。
- 3 分钟内看到主线、人物、看点、风险。

## 9. D7:低评级改写

目标:

- 完成加分项 #4。

任务:

- 根据 scorecard 识别低分项。
- 实现 rewrite API。
- 支持用户选段改写。
- 支持五类改写目标。
- 展示改写前后对比和说明。

验收:

- 低分项可点击改写。
- 改写说明目标和保留约束。
- 改写不是泛泛润色。

## 10. D8:Skill/反馈机制 + 结果迭代

目标:

- 完成加分项 #5。

任务:

- 实现反馈入口。
- 记录反馈。
- 支持生成 skill draft。
- 支持保存项目级 skill。
- 应用 skill 后报告新增或重排分析区块。

验收:

- 用户反馈"重点看前三分钟钩子"。
- 系统生成 skill。
- 保存后再次分析出现对应区块。

## 11. D9:部署 + README + 示例数据 + 录屏脚本

目标:

- 完成线上可访问。
- 准备提交材料。

任务:

- 部署前端。
- 部署后端。
- 配置环境变量。
- 准备 `.env.example`。
- 准备 README。
- 准备示例数据。
- 写录屏脚本。
- 跑完整 smoke test。

验收:

- 线上 demo 可访问。
- 示例剧本一键跑通。
- README 可让陌生人启动项目。
- 录屏脚本覆盖所有加分项。

## 12. D10:打磨 + 评估 + 修 bug + 展示材料

目标:

- 最终交付稳定。
- 所有文档和 demo 能支撑面试评估。

任务:

- 跑 eval。
- 修复阻塞 bug。
- 打磨 UI 文案。
- 确认所有加分项可见。
- 录制演示视频。
- 准备提交说明。
- 准备面试讲解稿。

验收:

- demo 从头到尾跑通。
- eval report 存在。
- README 完整。
- 录屏可独立说明项目价值。
- 提交材料清晰说明取舍和边界。

## 13. Build Gate

D2 之后进入 build 前必须满足:

- 需求文档完成。
- 竞品调研完成。
- 产品设计完成。
- 架构完成。
- 加分项计划完成。
- 交付计划完成。
- 工程规则完成。

若未满足,不进入代码实现。

## 14. Demo 验收清单

基础要求:

- 可以输入剧本。
- 可以输出分析结果。
- 可以交互追问。
- 可以实际体验。

核心能力:

- 决策卡片。
- coverage report。
- 多视角切换。
- 证据定位。
- scorecard。
- 改写。
- feedback skill。

加分项:

- 线上 URL 可访问。
- eval report 可查看。
- 数据分析可见。
- 改写可操作。
- skill 进化可演示。
- 前端展示服务理解效率。

## 15. README 结构

README 必须包含:

- 项目定位。
- 为什么不是普通摘要。
- 核心用户痛点。
- 功能列表。
- 架构说明。
- 本地启动。
- 环境变量。
- 在线 demo。
- 示例剧本。
- 评估方法。
- 加分项完成情况。
- 已知限制。
- 未来扩展。

## 16. 录屏脚本

建议 5-7 分钟:

1. 项目定位:30 秒。
2. 上传示例剧本:30 秒。
3. 展示决策卡和 coverage:1 分钟。
4. 点击证据定位:45 秒。
5. 切换投放/编剧/审核视角:1 分钟。
6. 多轮追问:45 秒。
7. 低分项改写:1 分钟。
8. skill 反馈:45 秒。
9. eval 和部署说明:45 秒。

## 17. 风险计划

### 17.1 时间不足

保底优先级:

1. Web demo。
2. 结构化报告。
3. 证据定位。
4. 多轮问答。
5. scorecard。
6. 改写。
7. skill。
8. eval 深化。

### 17.2 LLM 输出不稳定

处理:

- schema 校验。
- prompt 版本化。
- 失败重试。
- eval 回归。

### 17.3 部署失败

处理:

- D9 上午完成部署,留出修复时间。
- 本地录屏作为兜底。
- README 提供本地运行路径。

### 17.4 前端耗时过多

处理:

- 优先左右布局和证据联动。
- 图表简单即可。
- 不做复杂动画。

## 18. 最终交付包

最终提交建议包含:

- GitHub 仓库。
- 在线 demo URL。
- README。
- `docs/` 设计文档。
- `eval/` 评估样本和报告。
- 示例剧本。
- 演示录屏。
- 简短提交说明。

提交说明重点:

- 需求理解。
- 为什么不是摘要问题。
- 关键设计取舍。
- 加分项完成情况。
- 有效边界和失败边界。
