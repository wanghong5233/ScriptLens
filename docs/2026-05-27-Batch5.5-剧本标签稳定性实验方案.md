## 1. 实验目的

在真实短剧完整本上验证 `v2.0.0` 标签体系能否稳定地产生可用于前端展示和跨模态匹配的标签。

## 3. 实验模型

主实验固定一个千问模型，不混用。多个千问模型之间的一致性属于模型敏感性实验，本实验不做。

**首选 `qwen3-max`，兜底 `qwen-max-latest`**。

选型依据是任务画像与实测延迟，不是模型榜单排名。

任务画像：单情节 500–2000 字、结构化 JSON 输出、调用量约 2.2k – 2.6k 次（详见 §11）、需要稳定性优先于推理上限。

账号下可用千问文本模型实测：

| 模型 | 单次延迟 | 上下文 | 评价 |
| --- | ---: | --- | --- |
| `qwen3-max` | 0.8 s | 256K | 新一代旗舰推理，与本任务画像匹配，首选 |
| `qwen-max-latest` | 0.9 s | 32K | ScriptLens 现役主力，作兜底 |
| `qwen3.7-max` | 7.2 s | 1M | 优势在 35 小时级 agentic 长链路与百万上下文，与本任务错位；延迟约 qwen3-max 的 9 倍 |
| `qwen3.6-max-preview` | 12.3 s | 256K | 仍是 Preview，延迟高 |
| `qwen-long` | 0.6 s | 长文档 | 任务文本不长，不匹配 |
| `qwen-plus` | 0.6 s | 通用 | 已列入项目内 `FORBIDDEN_LLM_MODELS`，不进入候选 |

结果文档必须记录：provider、model name、prompt version、tag set version、seed（固定为 42）、temperature（固定为 0）。

## 4. 实验前提

实验期间必须关闭 LLM 缓存。

ScriptLens 后端有 `llm_cache`，同 prompt 同 seed 的第二次调用会直接返回上次结果，不再调用模型。若不关闭，重复实验测到的只是缓存命中率，不是模型输出稳定性。

是否关闭缓存属于实验有效性的前置条件，不是可调变量。

## 5. 实验参数

实验参数与 ScriptLens 生产 `LlmCaller.call_json_deterministic` 一致，唯一例外是关闭缓存（见 §4）：

| 参数 | 值 |
| --- | --- |
| `prompt` | 固定 |
| `temperature` | 0 |
| `seed` | 42 |
| `response_format` | `json_object` |
| 缓存 | 关闭 |
| 重复次数 | 5 |

5 次差异来自 provider 端 MoE 批次效应与硬件并发等非确定性，与 seed 无关。

## 6. 两层稳定性

剧本标签稳定性分两层。第二层只在第一层结论已知的前提下解读。

第一层是结构稳定性：同一个剧本能否稳定切出相近的情节单元。

第二层是标签稳定性：在固定情节、人物和关系后，同一个字段能否稳定打出同一个枚举值。

如果某个脚本的第一层不稳定，该脚本第二层的标签结果只作参考，不进入主统计。

术语：第一层称 `segmentation_stability`，第二层称 `tag_value_stability`。代码、目录、`manifest.json` 阶段名、报告字段统一使用这两个名字。

## 7. 重复次数为何取 5

最薄观测 scope 是剧级，样本数为 43。决策需要把字段判入四桶，对应 Wilson 95% 下界大致门槛 0.5 / 0.7 / 0.85。

设字段真实 pairwise 一致率为 p，单样本"N 次完全一致"概率约 p^C(N,2)。三档代表性 p 值下：

| pairwise 一致率 | N=3 | N=5 | N=7 |
| ---: | ---: | ---: | ---: |
| 0.99 | 0.97 | 0.90 | 0.81 |
| 0.95 | 0.86 | 0.60 | 0.34 |
| 0.90 | 0.73 | 0.35 | 0.11 |

N=3 三档都 ≥ 0.73，全挤进可用桶，看不出差别。
N=5 三档分别对应共享候选、fix、offline，刚好覆盖四桶决策。
N=7 进一步分辨力有限，情节级调用量翻倍。

所以两层均取 N=5，与视频侧 50×5 同口径，跨模态可比。

## 8. 第一层：结构稳定性

实验对象：情节单元切分。

对每个脚本按 §5 给出的口径（`seed=42`, `temperature=0`, prompt 固定，缓存关闭）重复运行情节切分 5 次。

观察指标取自文本分段评价的成熟方案（Pevzner & Hearst 2002 / Fournier 2013），不用简单的 boundary 集合 Jaccard，因为 Jaccard 把"边界相差 1 个 scene"与"完全错位"惩罚等同，没有近似匹配容忍。

| 指标 | 含义 | 出处 |
| --- | --- | --- |
| `unit_count_cv` | 5 次输出的情节数量变异系数 | sanity check |
| `window_diff_mean` | 5 次 boundary 集合两两 WindowDiff 取均值。0 = 完美，越大越差。窗口大小取均段长的一半，窗口内 boundary 计数不一致即记一次错误 | Pevzner & Hearst 2002 |
| `boundary_similarity_mean` | 5 次 boundary 集合两两 Boundary Similarity B 取均值。1 = 完美。允许边界相差 ≤ 2 个 scene 视为同一边界（near-miss tolerance） | Fournier 2013 |

结论分三档：

| 档位 | 含义 |
| --- | --- |
| 稳定 | 情节数量与边界基本不漂 |
| 可用待修 | 数量稳定但边界局部漂移 |
| 不稳定 | 情节数量或边界明显漂移 |

阈值建议（落地工程取此值，Stage 0 smoke 后可回调）：

| 档位 | 触发条件 |
| --- | --- |
| 稳定 | `window_diff_mean ≤ 0.15` 且 `unit_count_cv ≤ 0.10` |
| 不稳定 | `window_diff_mean ≥ 0.40` 或 `unit_count_cv ≥ 0.25` |
| 可用待修 | 介于两者之间 |

`boundary_similarity_mean` 在结果表里展示，但 verdict 阈值只用 `window_diff_mean + unit_count_cv`，避免两个指标矛盾时无法判定。

第一层结论按脚本输出。

## 9. 第二层：标签稳定性

实验对象：v2.0.0 标签体系下的全部字段，按载体分组：

- 剧级（script）；
- 集级（episode）；
- 情节级（plot_unit）；
- 人物（character）；
- 关系（relationship）。

第二层不在"剧本身份"上做观察，只在"scope 的字段"上做观察：同一字段在不同样本单元上 5 次是否能稳定输出同一枚举值。因此第二层样本量按 scope 独立采样，与剧本数无直接关系——只有 `script` scope 的样本单元才是剧本。

实验方式：

- 第一层完成后，把每个脚本的情节单元、人物实体、关系候选、集边界各固定一版（用第一层 `repeat=1` 的输出），作为第二层的"固定输入池"。第二层不再调用切分模型；
- 从每个 scope 的全局池里按固定 `random.Random(42)` 抽 `sample_size` 个单元，落盘到 `experiment_dir/samples.json`，运行期只读、`--resume` 时复用；
- 对每个 bundle 的所有字段按 §5 的口径（`seed=42`, `temperature=0`, prompt 固定，缓存关闭）在采样单元上重复运行 5 次；
- 比较 5 次输出。

样本量与视频侧同口径取 `N = 50`，依据：N = 50 时 Wilson 95% 下界可区分 0.5 / 0.7 / 0.85 三档阈值，刚好覆盖 §12 四桶决策；再加大对决策分桶边际收益趋零。`script` scope 总池只有 43 < 50，全跑。

| scope | 全局池规模（估） | 采样单元数 | 备注 |
| --- | ---: | ---: | --- |
| script | 43 | 43 | 总池 < 50，全跑 |
| episode | 数千 | 50 | 集边界从第一层 `repeat=1` 的剧本切分按"第 N 集"标题派生 |
| plot_unit | ~12 k | 50 | 跨剧本均匀采样，不按剧本均摊 |
| character | 数百 | 50 | 来源：第一层固定的人物实体抽取结果 |
| relationship | 数百 | 50 | 来源：第一层固定的关系候选 |

如果某剧本第一层判为"不稳定"，从该剧本派生的 plot_unit / character / relationship / episode 样本只参与逐字段展示，不进主统计。

核心指标：

| 指标 | 含义 |
| --- | --- |
| `avg agreement` | 5 次输出两两比较的一致率 |
| `stable` | 5 次输出完全一致的样本数 / 总样本数 |
| `Wilson 95% lower` | `stable` 比例的 Wilson 95% 下界 |

结果表与视频侧采用同一阅读方式：

## 10. 并发与一致性

### 10.1 并发度

DashScope 不暴露"事先查询配额"的 API，工程上只能 AIMD 自适应：

- 起步 `concurrency = 16`，上限 32，下限 4；
- 触发 `RateLimitError` / 429：`concurrency /= 2`，配指数退避（base 2 s，max 60 s，jitter ±10 %）重试同一请求；
- 连续 5 min 无 429：`concurrency += 2`，但不超过上限。

第一层（情节切分）按"剧本 × 重复次数"为并发单元，第二层（标签）按"bundle × 样本单元 × 重复次数"为并发单元。两层都用 `asyncio.gather` + `Semaphore`，监督协程定时调整 `Semaphore._value`。

### 10.2 一致性风险与措施

| 风险 | 是否成立 | 措施 |
| --- | --- | --- |
| LLM 调用本身并发 | 否 | HTTP 调用无副作用，每次都是独立 sample |
| `LlmCaller` in-flight 去重 | 否（已审计 `call_json_deterministic`） | cache 关闭后是 N 次独立 HTTP，无 single-flight |
| `llm_cache` 在并发下竞态 | 已关 | `SM_STABILITY_DISABLE_CACHE=1` 强制 `cache_enabled=False` |
| **跨 provider 自动兜底污染稳定性** | **成立** | `LlmCaller._RETRYABLE_EXC` 把 `RateLimitError` 视为可切 provider。实验期间**只配 `DASHSCOPE_API_KEY`，不配 `OPENAI_API_KEY`**，让限流走 §10.1 的 AIMD |
| `plot_units` 表并发写 | 否 | 不同 `script_id` 主键互不重叠 |
| 实验落盘 `repeats/*.json` | 否 | 每个 `(scope, sample_id, repeat)` 一个独立文件名 |
| `manifest.json` 并发写 | 成立 | 用 `asyncio.Lock` 串行化，写 `.tmp` 再 `os.replace` 原子替换 |
| `samples.json` 采样表并发读 | 否 | 启动时一次性生成，运行期只读 |
| 多协程 stdout `print` | 否 | Python `print` 行级原子 |
| DashScope 服务端幂等键复用 | 公开文档无此机制 | 监控：若多 repeat 返回 `system_fingerprint` 完全一致比例异常高，告警人工核查 |

## 12. 决策分层

每个字段进入下列其中一个桶：

| 决策桶 | 含义 |
| --- | --- |
| 可进入跨模态共享候选 | 字段足够稳定，可作为剧本与视频共同使用的核心字段 |
| 可用但建议聚合 | 字段在单情节上有抖动，但在剧级或集级聚合后稳定 |
| 需要收紧 prompt 后复测 | 当前不稳定，但漂移集中在少数枚举边界，可通过修定义恢复 |
| 暂不进共享内核 | 当前明显不稳定且漂移面较广 |

字段是否进入跨模态共享候选，需要同时参考剧本侧与视频侧结果。本实验只负责给出剧本侧结论。
