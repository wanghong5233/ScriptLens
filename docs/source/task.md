# 题目名称
设计并实现一个“剧本解析助手”，帮助用户高效理解长剧本。

## 一、背景
在短剧、网文、影视内容行业中，内容策划、编剧统筹、内容运营、选品、投放、审核等岗位，都会频繁接触大量陌生剧本。

这些剧本通常有几个共同特点：
- 篇幅长，完整阅读成本高；
- 信息密集，包含大量对白、场景切换和人物关系；
- 真正重要的信息往往分散在不同位置；
- 有些内容是铺垫，有些是噪音，有些则决定了整部作品是否值得继续看下去；
- 不同角色关注的重点并不相同：有人关心剧情主线，有人关心人物动机，有人关心卖点、节奏和传播潜力。

在真实工作场景中，用户通常没有足够时间从头到尾仔细阅读一份长剧本，但又不能只依赖一段粗略摘要来做判断。

他们真正需要的，不只是“这部剧讲了什么”，而是：
- 这部剧的核心主线是什么；
- 最关键的人物关系和冲突是什么；
- 主要看点、钩子、反转和爽点在哪里；
- 节奏是否清楚，前半段是否抓人；
- 角色动机是否成立，是否存在理解障碍；
- 这份剧本最值得关注的价值是什么；
- 它有哪些明显问题或风险；
- 用户是否值得继续投入更多时间阅读、讨论或推进。

因此，我们希望探索一种更高效的剧本理解方式，帮助用户在有限时间内建立对一份陌生剧本的有效认知。

## 二、要解决的问题
请你围绕以下问题展开思考：

> 如果一个用户面对一份较长、未经整理的剧本，怎样帮助他在尽可能短的时间内，尽可能准确地理解这份剧本？

这里的“理解”不等于简单压缩文本，也不等于只输出一个剧情简介。

我们更关心的是：如何把一份长剧本中真正有价值的信息提取出来、组织起来，并以一种对用户有帮助的方式呈现出来，让用户能够更快判断：
- 这部剧值不值得继续看；
- 重点应该看哪里；
- 它的核心价值是什么；
- 它的问题和风险在哪里。

换句话说，你需要面对的是一个长文本理解效率问题，而不是一个普通摘要问题。

## 三、任务目标
请围绕下面几个目标完成你的方案设计与实现。

### 1) 你认为用户的核心痛点是什么
请不要停留在“剧本太长”这一层面。请进一步回答：
- 用户真正缺的是什么；
- 他们为什么不能只看摘要；
- 他们做判断时最需要哪些信息；
- 哪些信息如果提取错了，会直接影响判断质量。

### 2) 你打算让这个助手输出什么
请说明你希望用户最终拿到的结果是什么样的。重点不在形式，而在信息设计是否真正有助于理解和决策。

例如你可以思考：
- 哪些信息应该被优先呈现；
- 哪些信息应该被压缩；
- 哪些信息应该保留原文依据；
- 是否需要分层呈现，满足不同时间预算下的阅读需求；
- 是否需要让用户能够快速定位到某个关键部分，而不只是被动接受一段结论。

### 3) 你如何判断这个助手是否真的有价值
请说明你认为一个好的解决方案，应该达成什么效果。例如但不限于：
- 帮用户节省多少时间；
- 帮用户减少哪些误判；
- 帮用户更快形成什么类型的判断；
- 在什么情况下用户会觉得它“有用”；
- 在什么情况下用户仍然会觉得它“不够用”。

### 4) 这个助手应该具备哪些核心功能
请从真实使用场景出发，定义这个助手至少需要具备哪些能力。不要求你穷举功能，但需要说明你为什么这样设计。

例如你可以考虑：
- 输入一份长剧本后，如何生成结构化分析；
- 用户是否可以围绕剧本继续追问；
- 用户是否可以要求查看某个判断的依据；
- 用户是否可以切换不同视角查看结果；
- 用户是否可以继续迭代、补充、修正解析结果。

我们希望看到的不是功能清单本身，而是你对“什么功能才真正解决问题”的判断。

## 四、交付内容
请提交一个可实际工作的 Agent。形式不限，可以是：
- CLI 工具；
- Chatbot；
- Web 应用；
- 其他你认为合适的交互形式。

基础要求如下：
- 可以输入一份剧本；
- 可以输出对剧本的分析结果；
- 可以与用户进行交互，而不是一次性静态输出；
- 可以让我们实际体验其工作方式。

提交形式不拘泥于固定模板，但你的最终提交内容中，应该能够让我们看出你对以下问题有清晰思考：
- 你如何理解这个问题；
- 你为什么认为这不是一个普通摘要问题；
- 你定义的核心用户需求是什么；
- 你的助手解决了哪些关键痛点；
- 你的输出结构为什么这样设计；
- 你的 Agent 在哪些情况下有效，哪些情况下可能失效；
- 你做了哪些取舍，以及为什么这样取舍。

你可以通过产品本身、演示方式、README、操作说明、录屏、对话过程或其他任何你认为合适的形式来体现这些内容。

## 五、加分项
以下内容不是必须，但如果完成，会显著加分。

### 1) 可部署、可访问
你的 Agent 不只是本地运行，而是可以部署到云上，并可被实际访问和体验。

### 2) 提供剧本解析效果的评估方法
请说明你如何评估这个助手的解析质量。例如：
- 解析是否准确；
- 是否遗漏关键信息；
- 是否帮助用户更快做判断；
- 是否能够稳定处理不同类型剧本。

我们更看重你是否有清晰的评估思路，而不是评估形式本身。

### 3) 增加数据分析能力
除了文本解析外，Agent 还能够从数据视角对剧本进行评价。例如对剧本的质量、可读性、结构完整度、节奏、潜在表现等给出某种等级判断或量化分析。

不要求唯一标准，但需要说明你的评价依据。

### 4) 对低评级剧本提供改写能力
当 Agent 判断剧本质量较低时，能够进一步给出优化建议，或直接对部分内容进行改写，使其朝更优方向调整。

我们希望看到你如何定义“改好”，以及你如何避免只做表面润色。

### 5) 具备可进化的 skill 机制
如果你的 Agent 能根据用户反馈、使用过程或新增需求逐步演化能力，会被视为加分。

例如但不限于：
- 可以根据反馈优化解析方式；
- 可以增加新的分析视角；
- 可以积累和调用特定 skill。

### 6) 有适合真实使用场景的前端展示
如果你的 Agent 提供了合适的前端展示，并且这种展示方式确实提升了理解效率、交互效率或结果可用性，也会被视为加分。

我们更关注的是展示方式是否服务于任务本身，而不是界面是否华丽。

## 六、我们期待看到的重点
我们希望通过这道题，理解你在以下方面的判断力与实现能力：
- 能否准确识别真实用户问题；
- 能否把模糊需求转化为清晰的问题定义；
- 能否围绕用户决策设计结果，而不是围绕文本做机械摘要；
- 能否做出一个真正可工作的 Agent，而不只是概念方案；
- 能否在功能、交互、结果质量和边界之间做出合理取舍；
- 能否意识到复杂文本理解中的歧义、风险与限制。

## 七、说明
- 不限制你的技术路线和实现形式；
- 不预设唯一解法；
- 可以自由定义重点用户、交互方式和结果结构；
- 请尽量避免空泛表述，重点说明你的设计判断和实现取舍；
- 我们更关注“是否真正解决问题”，而不是功能堆砌。
