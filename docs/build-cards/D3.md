# D3 Build Card: 仓库初始化与最小报告链路

## Goal

打通 ScriptLens 的第一条最小垂直链路:

> 加载示例剧本 -> 分段 -> 生成基础结构化报告 -> 前端展示

D3 的目标不是完成完整 Agent,而是证明技术栈、目录结构、数据契约和前后端链路能跑通。

## Inputs

- `samples/xiaoqie.txt`
- `docs/source/task.md`

## Outputs

- `ScriptDocument`
- `ScriptSegment[]`
- `BasicReport`
- 本地 Web 页面展示基础报告

## Contracts

### Dev Environment

- 本地 Python 环境使用 `.venv`,不使用 conda。
- 前端依赖使用 npm,必须生成 `package-lock.json`。
- D3 本地开发优先走 host 环境。
- Docker Compose 作为部署复现路径,不阻塞 D3 本地薄片,但需要补齐文件。
- D3 基础报告允许使用 deterministic mock,不被真实 LLM key 阻塞。

### ScriptDocument

- `id`
- `title`
- `source_type`
- `raw_text`
- `metadata`
- `created_at`

### ScriptSegment

- `id`
- `script_id`
- `label`
- `start_line`
- `end_line`

### BasicReport

- `script_id`
- `title`

- `segments`

## Steps

1. 初始化 Git 仓库和 `.gitignore`。
2. 创建 `backend/.venv` 并安装后端依赖。
3. 建立后端 Python 包和 FastAPI 最小应用。
4. 建立前端 Next.js/React/TypeScript 最小应用并生成 npm lockfile。
5. 补 Dockerfile 与 Docker Compose 复现路径。
6. 将示例剧本整理到 `samples/`。
7. 定义 D3 最小 Pydantic 数据契约。
8. 实现基于显式数字段落的分段器。
9. 实现基础报告生成器。D3 可先使用 deterministic mock,保留 LLM provider 接口位置。
10. 实现 API:
   - `GET /api/health`
   - `GET /api/sample`
   - `POST /api/scripts`
   - `POST /api/scripts/{script_id}/analyze`
   - `GET /api/scripts/{script_id}/report`
11. 实现前端页面:
   - 加载示例剧本。
   - 点击分析。
   - 展示分段和基础报告。
12. 用真实样本完成 smoke test。

## Non-goals

- 不做登录注册。
- 不做线上部署。
- 不做复杂向量数据库。
- 不做完整 scorecard。
- 不做 evidence refs 点击定位。
- 不做完整多轮问答。
- 不做改写和 skill。
- 不做真实市场预测。

## Risks

- 前端脚手架安装耗时过长。
- Windows 路径和中文文件名导致读取失败。
- 过早接入真实 LLM 导致 D3 被 API 配置阻塞。
- 报告字段自由发挥,后续难接前端。
- 只跑 host 环境导致后续部署不可复现。

## Risk Controls

- D3 允许基础报告先用 deterministic mock,不被 LLM key 阻塞。
- 样本统一放在 `samples/xiaoqie.txt`,避免 Docker 构建和 Windows shell 的中文路径问题。
- 所有输出先走 Pydantic schema。
- 前端只消费固定字段。
- 本地开发固定 `backend/.venv + npm`,部署复现固定 Docker Compose。

## Verification

Host verify:

```bash
cd backend
.\.venv\Scripts\python.exe -m pytest
cd ..\frontend
npm run build
```

Docker-ready verify:

```bash
docker compose config
```

如果 D3 结束时前端 Docker 镜像构建耗时过长,至少必须保证 Compose 配置可解析,并在 Record 中说明偏差。

### Deviations

- 最初前端依赖使用 `latest`,npm 拉到 `next@16`,要求 Node >= 20.9,与本机 Node 18 不兼容。已改为 `next@15` 并生成 lockfile。
- `pip install -e ".[dev]"` 首次失败,原因是 setuptools 在 flat layout 中误发现无关顶层目录。已通过 `tool.setuptools.packages.find` 限定只打包 `app*`。
- `npm run build` 首次失败,原因是 TS 未识别 side-effect CSS import。已补 `frontend/app/global.d.ts`。
- 样本已统一整理为 `samples/xiaoqie.txt`,原 `剧本样本/` 目录已删除。
- npm audit 当前仍提示 2 个 moderate vulnerabilities,未使用 `npm audit fix --force`,避免破坏 Next 15 版本约束。后续单独评估。

### Carry-over

- D4 开始补 evidence refs 和点击定位时,必须保留当前 `backend/.venv + npm + Docker Compose` 环境契约。
- D4 前不接真实 LLM,除非先完成 provider 抽象和 schema 校验。
- 需要在 D4 或部署前验证 `docker compose up --build`。
- 前端当前只是 D3 基础报告页,不能误认为已经完成 D6 真实报告 UI。
