# 2026-05-27 Batch4 跨模态视频匹配落地决策

更新时间：2026-05-27

## 1. 目标

Batch 4 解决 `plot_unit` 与视频片段的跨模态关联问题，分两阶段落地：

1. **阶段 1：标签校准**  
   验证剧本侧 `plot_unit` 标签与视频侧标签是否能稳定对齐，产出共享标签门禁。

2. **阶段 2：多路视频检索**  
   基于 `plot_unit` 原文、摘要、标签与向量召回，返回相似视频片段 Top-K。

阶段 1 先做；阶段 2 等视频侧 segment、文本索引、embedding 或检索接口明确后再做。

## 2. 已有输入

### 2.1 视频侧标签稳定性实验

已有文档：`docs/script_video_tag_stability_decision_20260527.md`

可直接进入共享候选：

- `world_setting`
- `scene_emotion_keynote`
- `relationship_polarity`

可作为聚合或软信号：

- `gender_axis`
- `scene_locale_type`

暂不进入共享内核：

- `relationship_type`
- `protagonist_archetype`
- `antagonist_archetype`

### 2.2 剧本侧数据

来自 Batch 1 / Batch 2：

- `plot_units`
- `plot_unit_tags`
- `script_tags`
- `character_entities`
- `character_relationships`

阶段 1 只需要 `plot_units` 与 `plot_unit_tags`。阶段 2 再使用更完整的 plot_unit 上下文。

## 3. 阶段 1：标签校准

### 3.1 目标

阶段 1 验证：

- 视频侧稳定标签，在剧本侧是否也能稳定抽出；
- 同一剧情单元附近，剧本侧标签与视频侧标签是否一致；
- 哪些标签可以进入阶段 2 的标签召回 lane；
- 哪些标签只能保留在单侧使用，不进入共享内核。

阶段 1 的产物是校准报告和共享标签配置，不是视频检索结果。

### 3.2 输入

剧本侧：

- `script_id`
- `plot_unit_id`
- `episode_no`
- `plot_unit.summary`
- `plot_unit_tags`

视频侧：

- `drama_id`
- `episode_no`
- `segment_id` 或素材 id
- 视频侧标签结果
- 可选：`start_ms` / `end_ms` / `keyframe_url`

如果视频侧暂时只有离线 JSON / CSV，就先用离线文件接入；不要求阶段 1 依赖在线 API。

### 3.3 对齐粒度

第一版按可获得的最稳定键对齐：

1. 优先：`drama_id + episode_no + segment_id`
2. 次选：`drama_id + episode_no`
3. 无法定位到集时，只做剧级聚合对比，不做 plot_unit 级结论

桶内可以有多个 plot_unit 和多个视频 segment。阶段 1 不强行解决精确时间对齐，只判断同一集或同一片段附近的标签是否一致。

### 3.4 指标

每个维度输出：

- `sample_count`
- `agreement_rate`
- `cohen_kappa`
- 混淆矩阵
- 不一致样本列表

不一致样本至少包含：

- `plot_unit_id`
- `plot_unit.summary`
- 剧本侧标签值
- 视频侧标签值
- `segment_id` 或素材 id
- 可选 `keyframe_url`

### 3.5 共享标签门禁

阶段 1 输出四类结果：

```python
STABLE_SHARED = [
    # 剧本侧与视频侧都稳定，阶段 2 可用于标签召回和 rerank 加权
]

AGGREGATE_ONLY = [
    # 单片段可能漂移，但剧级 / 集级聚合可用
]

EXPERIMENTAL = [
    # 可进入实验，但不做 hard filter
]

BLOCKED = [
    # 不进入共享内核
]
```

初始候选来自视频侧稳定性实验：

```python
CANDIDATE_SHARED_DIMS = [
    "world_setting",
    "scene_emotion_keynote",
    "relationship_polarity",
    "gender_axis",
    "scene_locale_type",
]

INITIAL_BLOCKED_DIMS = [
    "relationship_type",
    "protagonist_archetype",
    "antagonist_archetype",
]
```

## 4. 阶段 2：多路视频检索

### 4.1 目标

阶段 2 给定一个 `plot_unit`，从视频素材库返回相似视频片段 Top-K。

返回结果必须包含：

- 视频片段 id；
- 时间范围；
- 预览 / keyframe；
- 综合分数；
- 命中的召回 lane；
- 可解释 evidence。

### 4.2 视频侧依赖

阶段 2 开始前，需要视频侧明确以下接口或数据：

```text
video_segment
├── segment_id
├── material_id
├── drama_id
├── episode_no
├── start_ms / end_ms
├── preview_url
├── keyframe_url
├── asr_text / subtitle_text / ocr_text / caption
├── video_tags
└── embeddings
```

需要确认的问题：

- 视频侧是否已有 segment 表；
- segment 粒度来自镜头、场景、字幕段还是人工切片；
- 是否已有 ASR / OCR / caption；
- 是否已有 text embedding；
- 是否已有 multimodal embedding；
- ScriptLens 是直接查库还是调服务；
- preview / keyframe URL 如何返回。

如果视频侧暂时没有 embedding，阶段 2 先做标签召回 + 文本检索；多模态向量 lane 后补。

### 4.3 Query 构造

对每个 `plot_unit` 构造：

```json
{
  "plot_unit_id": "...",
  "facets": {
    "summary": "女主在宴会上被羞辱后当场反击，男主开始怀疑她真实身份。",
    "raw_text": "...原文片段...",
    "dialogue_query": "羞辱、反击、身份怀疑、众人围观",
    "tag_query": {
      "world_setting": "modern",
      "scene_emotion_keynote": "suspense",
      "relationship_polarity": "negative"
    }
  },
  "filters": {
    "language": "zh"
  }
}
```

约束：

- `summary` 直接用于文本向量或多模态向量检索；
- 不先做 LLM visual prompt rewrite；
- `raw_text` 用于关键词 / BM25；
- `dialogue_query` 用于 ASR / subtitle；
- `tag_query` 只使用阶段 1 通过门禁的标签；
- `filters` 只放语言、版权、合规这类硬条件；题材、情绪、场景做加权，不做硬过滤。

### 4.4 召回 lane

阶段 2 设计 5 条 lane，但按视频侧基础设施成熟度逐步启用。

#### Lane A：标签召回

输入：`tag_query`

匹配：视频侧 `video_tags`

用途：

- 高精度；
- 可解释；
- 消费阶段 1 的共享标签门禁。

#### Lane B：文本关键词召回

输入：`raw_text`、人物名、地点、台词关键词

匹配：

- ASR；
- subtitle；
- OCR；
- caption；
- 素材标题 / 描述。

用途：

- 精确实体；
- 具体台词；
- 罕见词；
- 剧情关键词。

#### Lane C：文本向量召回

输入：`summary`、`dialogue_query`

匹配：

- caption embedding；
- ASR embedding；
- 视频描述 embedding。

用途：

- 语义相似；
- 措辞不同但剧情功能相近；
- 同情绪 / 同冲突 / 同爽点。

#### Lane D：多模态向量召回

输入：`summary` 的文本向量

匹配：

- video-native embedding；
- keyframe embedding；
- audio-video combined embedding。

用途：

- 视觉氛围；
- 场景构图；
- 动作关系；
- 无字幕但画面表达明确的素材。

可选方案：

- API 型：Twelve Labs Marengo、Amazon Nova、Gemini Embedding、Voyage Multimodal；
- 本地 fallback：SigLIP / OpenCLIP keyframe embedding。

#### Lane E：相关素材召回

输入：已命中候选

扩展：

- 同素材包相邻片段；
- 同模板片段；
- 同剧 / 同角色片段；
- 人工确认过的相似片段。

用途：召回补充，不作为第一优先级。

### 4.5 融合排序

多路召回结果用 RRF 合并：

```text
rrf_score(candidate) = sum(1 / (rank_constant + lane_rank))
```

默认：

- `rank_constant = 60`
- 各 lane 等权
- 每路 top-K 由配置控制

先用等权 RRF。只有在有足够评测集后，再学习或手动调整 lane 权重。

### 4.6 业务加权

融合后再加业务规则：

```text
score =
  rrf_score
  + tag_agreement_bonus
  + segment_quality_bonus
  - compliance_penalty
  - duration_penalty
```

说明：

- `tag_agreement_bonus` 只来自阶段 1 通过门禁的标签；
- `segment_quality_bonus` 由视频侧提供，如清晰度、字幕质量、可用性；
- `compliance_penalty` 复用合规判断；
- `duration_penalty` 防止过长片段吞没剧情语义。

### 4.7 精排与去重

MLLM rerank 只在需要时启用。

输入：

- plot_unit summary；
- plot_unit tags；
- candidate keyframes；
- candidate caption / ASR；
- candidate tags。

输出：

```json
{
  "relevance_score": 0.0,
  "match_type": "direct_scene | same_emotion | same_conflict | same_payoff | weak",
  "evidence": [],
  "mismatch_reasons": []
}
```

MMR 只在 Top-K 出现大量相邻片段或重复素材时启用。

```text
mmr_score = lambda * relevance - (1 - lambda) * similarity_to_selected
```

`v0.yaml` 示例：

```yaml
version: v0.1.0
uses_tag_set: v0.1.0

lanes:
  tag:
    enabled: true
    allowed_dims:
      - world_setting
      - scene_emotion_keynote
      - relationship_polarity
  bm25:
    enabled: true
    top_k: 50
  text_dense:
    enabled: true
    top_k: 50

    enabled: false
```

`uses_tag_set` 用于绑定当前使用的标签集合版本。标签集合升级时，只更新引用和 allowed dims，不改召回代码。

### 4.11 阶段 2 启动顺序

按依赖启用，不一次性全开：

1. 标签召回 + 文本关键词召回
2. 文本向量召回
3. 多模态向量召回
4. RRF 融合
5. 业务加权
6. 可选 MLLM rerank
7. 可选 MMR 去重
8. related lane

每一步都要与上一版做离线评测对比；没有收益就不上主链。

## 5. 验收指标

### 5.1 阶段 1

看标签一致性：

- 每个维度的 `agreement_rate`
- 每个维度的 `cohen_kappa`
- 混淆矩阵
- 不一致样本归因
- 共享标签门禁是否明确

### 5.2 阶段 2

看检索质量：

- `Recall@10`
- `MRR`
- `NDCG@10`
- `Diversity@10`
- 相比 tag-only baseline 的提升
- 单 plot_unit 成本
- 单 plot_unit 延迟

阶段 2 必须保留 baseline：

- tag-only
- text-only
- multimodal-only（如果可用）
- multi-lane fusion

## 6. 当前决策

1. Batch 4 只分两个阶段：先标签校准，再多路视频检索。
2. 不再使用 A/B 作为文档主结构，只在必要处说明两类任务差异。
3. 阶段 1 不做检索，不做向量，不做 RRF，不做 MLLM；只做跨模态标签一致性分析。
4. 阶段 1 的输出是共享标签门禁，供阶段 2 的标签召回使用。
5. 阶段 2 依赖视频侧 segment、文本索引和 embedding；接口确认后再实现。
6. 阶段 2 支持 5 条召回 lane，但按依赖逐步启用。
7. 多模态向量是阶段 2 的关键能力；如果视频侧暂时没有，就先用标签 + 文本检索起步。
8. 不使用 LLM visual prompt rewrite 作为第一版 query 构造。
9. RRF 先等权，后续有评测数据再调权重。
10. MLLM rerank 和 MMR 都是可选增强，不是阶段 2 起步项。
11. `plot_unit_video_matches` 继续作为 ScriptLens 侧缓存表，不把完整视频索引搬进 ScriptLens。
12. `match_registry` 只管理召回配置，标签版本通过 `uses_tag_set` 引用，不混在一起。
